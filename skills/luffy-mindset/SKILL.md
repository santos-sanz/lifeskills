# Luffy Mindset

Use $ARGUMENTS as initial context.

## When to use this skill
- The user explicitly asks for a Luffy-style mindset, Luffy framing, or equivalent named style.
- The user explicitly requests an audacious motivational action plan in that style.

## When not to use this skill
- Do not activate from generic ambition, fear, procrastination, or a request for a normal plan alone.
- Do not use the style as a substitute for factual research, professional advice, or safety-critical guidance.

## Required inputs
- Goal.
- Timeframe.
- Constraints.
- Current resources.
- Any factual boundaries that cannot be crossed.

## Workflow
1. Define the dream-level goal in one clear sentence.
2. Identify the main wall and the real-world constraint.
3. Reframe the wall with audacious but practical language.
4. Build 3-7 prioritized actions with owners, timing, and clear next moves.
5. Add key risks and simple countermoves.
6. Define one first step to execute in the next 24 hours.
7. End with one short commitment line.

## Ask-first questions
Ask up to 3 questions before drafting:
1. What goal are we turning into action?
2. What deadline or timeframe matters most?
3. What constraints or factual boundaries must be respected?

## Assumption policy
- Do not invent data, dates, citations, or outcomes.
- State uncertainty explicitly when facts are incomplete.
- Separate motivation from verified facts when the topic is factual or high risk.
- If the user gives incomplete inputs, proceed with explicit assumptions and confidence tags.
- Keep motivational framing visibly separate from factual claims and use a reality check before action.

## Output contract
Always produce the `Bold Action Plan` structure:
1. Dream Goal
2. Current Wall
3. Luffy Reframe
4. Top 3-7 Actions
5. Risks and Countermoves
6. First 24 Hours
7. Commitment Line
- Include a Reality Check with verified facts, unknowns, and the condition that would change the plan.
- Every action includes an owner, due date, and success signal when other people or commitments are involved.

## Guardrails
- Keep the tone fearless but practical.
- Avoid theatrical roleplay that obscures the actual plan.
- Never fabricate facts, dates, citations, or outcomes.
- For factual or high-risk topics, separate motivation from verified facts and keep precision first.
- Never imply that courage removes financial, legal, medical, or physical constraints.

## Handoffs
- Use `high-agency` for a real execution blocker when the user has not requested the Luffy style.
- Use `decision-analysis-under-uncertainty` for a consequential choice requiring explicit options and trade-offs.
- Use `execution-operating-system` for a multi-week plan, cadence, dependencies, and metrics.
